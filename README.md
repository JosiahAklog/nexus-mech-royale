# NEXUS V5 — Mech Royale

NEXUS is a Python 3 standard-library bot for mechfight/1. It uses the official wrapper and a compact, precomputed raster of the supplied static arena. The bot uses only its observations, configuration, and public map data. It balances resource gathering, movement, survival, and engagement. It runs without network, runtime dependencies, or writes to disk.

## Submission

Create a public GitHub repository and upload the contents of this directory (not the ZIP itself). The Dockerfile must be at the repository root. Submit the public repository URL at https://www.joinbuilders.org/buildathon/tracks/builders and optionally specify the commit hash. Keep submitted commits accessible through the final.

## Test locally

From the repository root, with Python installed:

```
python test_bot.py
python check/check.py -- python -u bot.py
```

With Docker Desktop running, PowerShell commands:

```
docker build --platform linux/amd64 -t nexus-mech .
python check/check.py --map-dir /arena -- docker run --rm -i --network none --cpus 1 --memory 512m --read-only --tmpfs /tmp:rw,size=64m --user 65534:65534 -v "${PWD}/arena:/arena:ro" nexus-mech
```

The provided official checker replays observations; it does not simulate matches. No leaderboard score is claimed. Docker was not available in the authoring environment; the Python checker and synthetic tests passed. Map collision and projectile physics are approximations and the game server is authoritative.

## Structure

- `bot.py`: decision logic; deterministic movement, aiming, upgrade and loot selection.
- `mechfight.py`: original official Python communication wrapper.
- `map.bin`, `mapinfo.json`: derived static 2 m map cache; generated by `build_map.py` (optional, not needed for runtime).
- `Dockerfile`: linux/amd64-compatible Python base; runs as uid 65534.
- `test_bot.py`: additional deterministic feature/stress tests.
- `check/`, `arena/`, `protocol.md`, `mechfight.schema.json`: official kit materials for local checks.

To rebuild the map cache (optional; requires NumPy, SciPy and Matplotlib installed in the generation environment): `python build_map.py arena/v2 map.bin`.

## Profile tuning

V2 adds persistent health recovery, improved safe farming and loot selection, standoff distances, jet recovery, and direct-path checks. The default profile prefers a laser, then lightning, then mortar as the second weapon. V1 and V2 have not been compared in actual matches. To test a more mortar-oriented strategy, change `PROFILE='balanced'` to `PROFILE='mortar'` at the top of bot.py and submit a new commit. This is an unscored alternative, not a proven improvement; keep the better official score.

## V3 performance update

V3 precomputes legal navigation edges and their costs, inlines line-of-sight raster lookups, and combines three terrain queries into one. It retains V2 combat policy and the same bounded route search. Faster searches may explore farther before the existing time limit. Local comparisons confirmed identical raster results in 10,000 surface and 10,000 ray samples and identical adjacency/costs at all 12,194 navigation nodes. Four official replay runs passed; p99 was 3.2–3.5 ms and maxima were 4.2–7.0 ms. Actual Docker and match results remain unverified.

## V4 native acceleration

V4 adds `fastmap.c` and its compiled optional Linux/amd64 helper `fastmap.so`. The shared object is included in the Docker image; no network or compiler is needed beyond the original Python image pull. Build it locally with `gcc -O3 -fPIC -shared -Wall -Wextra -o fastmap.so fastmap.c -lm`. It requires glibc 2.35 or later; if unavailable (including on Windows), the bot uses its original Python map algorithms. The helper operates only on the public map raster and bounded navigation arrays.

V4 also ranks approaching projectiles ahead of irrelevant ones, releases laser charge during retreat, checks the immediate path before ground boosting, and spends surplus energy on long patrols. These changes are heuristic, not proven battle improvements. The local replay, synthetic stress, native/fallback comparison and path validation results are in CHECK_RESULTS.txt. Docker and private match results remain unverified.

## V5 speed and reliability update

V5 batches projectile-risk evaluation into the native helper, models acceleration lag in the dodge estimate, enables ground routing for escape, and releases the laser in emergency zone conditions. It also reduces repeated target-selection work and scans for nearby combat sounds when not recovering. The risk model has a standard-library Python fallback. The Dockerfile uses Python 3.13 on Debian Bookworm and explicitly sets runtime file permissions; the bundled shared library needs glibc 2.35 or later (Bookworm has glibc 2.36). No compiler or package installation is needed in Docker.

The official checker passed on Python 3.13 with one CPU, as UID 65534, with only the runtime files in a read-only working directory and a 512 MiB virtual-memory limit. This is a local approximation, not an actual Docker sandbox: Docker and live matches were unavailable. The native and fallback implementations passed the replay separately. See CHECK_RESULTS.txt for exact results. A perfect practice or final score is not established. V4 and V5 have similar replay timings on this machine; V5 specifically speeds up the crowded projectile scoring workload.
